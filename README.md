## Структура

```
src/lab05/llm.py           единый клиент: OpenAI / Anthropic / Ollama (переключение через .env)
src/lab05/schemas.py       pydantic-схемы Quest, Item, DialogueTurn
src/lab05/generators.py    3 генератора с валидацией и повтором при невалидном JSON
prompts/*.md               системные промпты (версионируются!)
data/out/                  корпус: quests.json, items.json
app/streamlit_app.py       демо
```

```bash
cp .env.example .env   # вписать ключ или LLM_PROVIDER=ollama
pip install -r requirements.txt   # или: make install (все команды: make help)
python -m lab05.generators --quests 10 --items 20
streamlit run app/streamlit_app.py
```

## Пример выполнения

**Где это в играх.** AI Dungeon целиком построен на генерации текста языковой моделью. Ubisoft сделала внутренний
инструмент Ghostwriter: он пишет черновики коротких реплик NPC («барков»), а сценарист выбирает и правит лучшие.
В RPG тысячи предметов и побочных квестов, и описания к ним — одна из самых рутинных частей работы.

**Зачем:** модель быстро даёт объём и разнообразие, но игре нужен строгий формат — движок не прочитает «почти JSON».
Поэтому в ЛР главное не сама генерация, а схемы, валидация и повтор при ошибке: без них контент нельзя подать в игру.

**Квест**, прошедший валидацию схемой `Quest` (`src/lab05/schemas.py`):

```json
{"title": "Соль для мёртвого озера",
 "giver": "Травница Вейла",
 "objective": "Добыть три кристалла соли со дна пересохшего озера",
 "steps": ["Выяснить у рыбаков, где был глубокий омут", "Спуститься на дно с фонарём", "Отбиться от солевых крабов", "Вернуться к травнице до заката"],
 "reward": "Зелье ночного зрения и 80 монет",
 "difficulty": 3}
```

**Предмет** (схема `Item`):

```json
{"name": "Клинок пепельного рассвета", "type": "weapon", "rarity": "epic",
 "description": "Выкован в остывшем жерле вулкана, в темноте слабо тлеет.", "stats": {"damage": 34, "fire": 8}}
```

**Реплика NPC** (схема `DialogueTurn`, персона «Торговец Барт» из `prompts/personas.md`):

```json
{"npc": "Торговец Барт", "text": "Зелье лечения? Двадцать монет! А за пять сверху расскажу, какой корабль вчера пришёл в порт без команды.",
 "emotion": "cheerful", "options": ["Купить зелье", "Купить зелье и слух", "Поторговаться", "Уйти"]}
```

**Пример таблицы качества** (в отчёт):

| Генератор | Запросов | Валидный JSON с 1-й попытки | После повтора | Уникальных названий |
|---|---|---|---|---|
| Квесты | 10 | 8 / 10 | 10 / 10 | 10 / 10 |
| Предметы | 20 | 17 / 20 | 20 / 20 | 19 / 20 |

К таблице добавьте 2–3 неудачных ответа модели с разбором причины (лишний markdown, выход за перечень `rarity`,
повтор сюжетов) и что вы поменяли в промпте. Промпты храните в `prompts/`, каждое изменение отдельным коммитом.

## Как сдавать

1. Работайте в этом репозитории, коммитьте по шагам (`step-1`, `step-2` …) — история коммитов учитывается.
2. Отчёт пишите в `docs/report.md` (черновик по разделам, 6–8 стр.), затем перенесите в официальный шаблон отчёта, принятый на кафедре, и экспортируйте в PDF (`docs/report.pdf`).
3. Видео — на YouTube/Диск, ссылку в README и в отчёт. Файлы видео в git не кладём.
4. Готовую работу отметьте тегом `git tag v1.0 && git push --tags` и создайте Release.
